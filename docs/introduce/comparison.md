## 二、逐项能力拆解

### 2.1 技术栈与二次开发

| 产品 | 二次开发语言 | 对企业现有系统的友好度 |
|------|--------------|------------------------|
| **AntSK** | C# / .NET 9 | ✅ 与 ASP.NET 系统同栈，零迁移成本；强类型 + 编译期检查；NuGet 依赖管理 |
| Dify | Python / TypeScript | 与 .NET 系统集成需跨语言网关 |
| RAGFlow | Python / Vue | 与 .NET 系统集成需跨语言网关 |
| MaxKB | Python | 与 .NET 系统集成需跨语言网关 |
| FastGPT | TypeScript / Node.js | 与 .NET 系统集成需跨语言网关 |

> **结论**：若你的技术栈是 .NET / C#，AntSK 是唯一能原生融入的企业级开源方案。

### 2.2 部署与数据合规

| 产品 | 私有化部署 | 完全离线运行 | 国产数据库 | 信创环境 |
|------|-----------|--------------|-----------|----------|
| **AntSK** | ✅ Docker / 源码 | ✅ 全链路离线 | ✅ 含达梦等 | ✅ 支持 |
| Dify | ✅ | 部分（依赖外部模型服务） | 需适配 | 需额外工程 |
| RAGFlow | ✅ | 需自行配置本地模型 | 需适配 | 需额外工程 |
| MaxKB | ✅ | ✅ | 良好 | ✅ 较好 |
| FastGPT | ✅ | 有限 | 较弱 | 较弱 |
| 360AI知识库 | ❌ 闭源托管 | ❌ | — | 依云服务 |

> **结论**：金融、政务、医疗、军工等**数据敏感 + 信创要求**场景，AntSK 与 MaxKB 是主要候选；AntSK 在 .NET 集成与软硬一体交付上更进一步。

### 2.3 文档解析能力

| 产品 | 标准 Office 文档 | 复杂表格 | 扫描件 / 图文混排 |
|------|------------------|----------|-------------------|
| **AntSK** | ✅ | 中等（可配 OpenCV + OpenVINO OCR） | 中等 |
| RAGFlow | ✅ | ✅ 强 | ✅ 最强 |
| Dify | ✅ | 中等 | 中等 |
| MaxKB | ✅ | 中等 | 中等 |
| FastGPT | ✅ | 中等 | 中等 |

> **结论**：若文档以**扫描件、复杂表格、图文混排**为主且解析精度是第一优先，RAGFlow 更合适；若为标准 Office 文档，各产品差异不大。

| Dify | ✅ | ❌ | 中，需自行准备算力与环境 |
| RAGFlow | ✅ | ❌ | 中，需自行准备算力与环境 |

## 四、常见问题

**Q：AntSK 相比 Dify 生态小，是不是不够成熟？**
A：生态规模与成熟度是两个维度。AntSK 的版本迭代持续活跃，开源版已包含完整的企业知识库与对话能力，并具备内置 RBAC、多租户与信创适配这些 Dify 社区版并不原生提供的能力。生态规模小意味着第三方插件少，但也意味着技术栈统一、技术债务少、可维护性高。

**Q：AntSK 能替代 RAGFlow 吗？**
A：取决于文档复杂度。AntSK 已集成 OCR（OpenCV + OpenVINO）并支持自定义切片策略，标准 Office 文档场景可完全胜任；若文档以扫描件与复杂表格为主，建议先用真实语料做小规模验证。

**Q：可以只用 AntSK 的知识库能力，不用它的对话界面吗？**
A：可以。AntSK 提供 OpenAI 兼容 API（`POST /api/v1/chat/completions`、`POST /api/v1/rerank`），可将 AntSK 作为知识库后端嵌入你已有的应用系统。
